# Quick Start

Try the prebuilt Gateway and Agent without a source checkout, Go, or `make`.
This guide uses public development credentials and must run only on a trusted
local computer. For production configuration, follow [Deployment](/operations/deployment).

## 1. Download the two release assets

From the same [GitHub Release](https://github.com/viewlegacy/onprest/releases),
download the archive for your OS/CPU and the matching
`onprest-X.Y.Z-quickstart.tar.gz`. The binary archive contains
`onprest-gateway` and `onprest-agent`; the Quick Start archive contains the
example env, YAML, database Compose file, and SQL initialization file.

For a production installation, verify downloads with the published checksum
and artifact attestation before extracting them; see
[Binary Release Installation](/operations/deployment#binary-release-installation).
Verification is optional for this disposable local trial. Extract both
archives before continuing.

The following commands assume the two extracted directories are siblings and
use Linux/macOS shell syntax. Replace `X.Y.Z` and `<os>-<arch>` with the names
you downloaded:

```bash
cd onprest-X.Y.Z-<os>-<arch>
QUICKSTART=../onprest-X.Y.Z-quickstart
```

## 2. Prepare PostgreSQL

Choose one of these options:

- If you need a disposable database, use Docker Compose:

  ```bash
  docker compose -f "$QUICKSTART/postgres.compose.yml" up -d --wait
  ```

  This creates `legacy` on `127.0.0.1:5432`, seeds `customers`, and creates a
  `capability_user` with `SELECT` and column-level `UPDATE (name)` only.
- If you already have PostgreSQL, create an empty disposable `legacy` database
  and run `postgres-init.sql` with an account allowed to create roles and grant
  permissions. Then adjust the host, port, database name, and credentials in
  `capability.postgres.yaml`. If the database is not named `legacy`, also change
  the `GRANT CONNECT ON DATABASE legacy` line in the SQL file. This route needs
  no Docker. Do not run the SQL against a production database.

  For example, after creating the empty database, an administrator can run:

  ```bash
  psql -h localhost -p 5432 -U YOUR_ADMIN_USER -d legacy \
    -v ON_ERROR_STOP=1 -f "$QUICKSTART/postgres-init.sql"
  ```

If port 5432 is occupied, use another port and update both the Compose file
and Agent YAML. Docker is only a way to supply an evaluation database; it is
not an Onprest runtime dependency.

## 3. Validate and start the binaries

```bash
./onprest-agent validate --config "$QUICKSTART/capability.postgres.yaml"
```

Validation checks the YAML, DB connection, and SQL preparation. If it fails,
see [Troubleshooting](/operations/troubleshooting#db-ping-or-explain-startup-failure).

Start the Gateway:

```bash
set -a
. "$QUICKSTART/gateway.env"
set +a
./onprest-gateway
```

In another terminal, start the Agent using the absolute path of the extracted
Quick Start directory (or set `QUICKSTART` again there):

```bash
./onprest-agent --config "$QUICKSTART/capability.postgres.yaml"
```

### Windows PowerShell

After extracting the Windows binary zip and Quick Start tarball as sibling
directories, run these commands in PowerShell. Use a new terminal for the Agent
and repeat the first three assignments there:

```powershell
$Version = 'X.Y.Z'
$BinaryDir = (Resolve-Path ".\onprest-$Version-windows-amd64").Path
$QuickStartDir = (Resolve-Path ".\onprest-$Version-quickstart").Path
docker compose -f "$QuickStartDir\postgres.compose.yml" up -d --wait
& "$BinaryDir\onprest-agent.exe" validate --config "$QuickStartDir\capability.postgres.yaml"
Get-Content "$QuickStartDir\gateway.env" |
  Where-Object { $_ -match '^GATEWAY_[A-Z_]+=' } |
  ForEach-Object {
    $name, $value = $_ -split '=', 2
    [Environment]::SetEnvironmentVariable($name, $value.Trim("'"), 'Process')
  }
& "$BinaryDir\onprest-gateway.exe"
```

In the second terminal:

```powershell
$Version = 'X.Y.Z'
$BinaryDir = (Resolve-Path ".\onprest-$Version-windows-amd64").Path
$QuickStartDir = (Resolve-Path ".\onprest-$Version-quickstart").Path
& "$BinaryDir\onprest-agent.exe" --config "$QuickStartDir\capability.postgres.yaml"
```

Use the health, REST, OpenAPI, and MCP URLs below with PowerShell's
`Invoke-RestMethod` or another HTTP client.

## 4. Verify health, REST, OpenAPI, and MCP

```bash
curl -sS http://localhost:8080/healthz
```

The response should include `"agent_connected":true`. The plaintext key below
is public and works only with the bundled evaluation configuration:

```bash
export ONPREST_API_KEY='orjrqqPeX8FXhsECOnrnOr6oa70pOYjyeUWmxTbaZrM'
curl -sS -H "Authorization: Bearer $ONPREST_API_KEY" \
  -H 'Content-Type: application/json' -d '{"customer_id":1}' \
  http://localhost:8080/api/v1/capabilities/get_customer
```

The REST result contains Ada Lovelace. Check the API description and MCP tool
list with the same key:

```bash
curl -sS -H "Authorization: Bearer $ONPREST_API_KEY" \
  http://localhost:8080/openapi.json
curl -sS -H "Authorization: Bearer $ONPREST_API_KEY" \
  -H 'Content-Type: application/json' \
  -H 'MCP-Protocol-Version: 2025-11-25' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' \
  http://localhost:8080/mcp
```

You should see `get_customer` and `update_customer`. For the complete
capability contract, see the example YAML in the Quick Start asset and
[Capability YAML](/agent/capability-yaml).

## 5. Clean up

Stop the two binaries with Ctrl+C. If you used the disposable Docker database,
remove its container and volume:

```bash
docker compose -f "$QUICKSTART/postgres.compose.yml" down -v --remove-orphans
```

To build from source instead, see [CLI Reference](/reference/cli#build-from-source).
