# Test Commands

These commands are for contributors and release maintainers. Installing a
published binary does not require Go, Docker, or a test run.

| Command | Use |
|---|---|
| `go test ./...` | Run unit and repository-contract tests without a database. |
| `go vet ./...` | Check Go code for common mistakes. |
| `make vulncheck` | Check the source for reachable known vulnerabilities. |
| `make test-it` | Run database-backed integration tests. |
| `make test-it-postgres-ci` | Run the PostgreSQL CI suite repeatedly. |
| `make test-it-postgres-stability` | Check behavior when PostgreSQL becomes unavailable. |
| `make test-it-all-db` | Run conformance tests across PostgreSQL, MySQL, SQL Server, and Oracle. |
| `make test-it-database-tls` | Run real-database TLS checks for those four databases, including private CA, hostname, and supported client-certificate behavior. |
| `make test-it-docker-ops` | Check Docker image and Compose behavior. |
| `make test-it-release-gate` | Run the Linux integration portion of the release gate. |

The integration targets use Docker to start test databases. To fail instead of
skipping container-backed tests when Docker is unavailable, set
`ONPREST_IT_REQUIRE_CONTAINERS=1`. For example:

```bash
ONPREST_IT_REQUIRE_CONTAINERS=1 make test-it
```

Use `-onprest-it-db=postgres`, `mysql`, `sqlserver`, `oracle`, or `all` with
`go test -tags=integration ./it/... -args` to select a database. PostgreSQL
is the default for `make test-it`.

Maintainers create candidate archives and scan the distributed binaries with
`make release-artifacts VERSION=X.Y.Z RELEASE_TAG=vX.Y.Z RELEASE_SHA=<sha>
RELEASE_READY_URL=<url>`. The complete release also requires native service
checks and the exact-commit `release-ready` job; see [How Releases Are Checked](/operations/release-gate).
