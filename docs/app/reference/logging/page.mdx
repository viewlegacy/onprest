# Logging Reference

## Gateway

The gateway writes JSON Lines to stdout.

Request event fields:

| Field | Description |
|---|---|
| `protocol` | `rest` or `mcp` |
| `request_id` | Gateway-generated ULID; separate from an MCP JSON-RPC `id` |
| `timestamp` | UTC event time in RFC 3339 format |
| `event` | Always `request` for a request event |
| `capability` | capability name when available |
| `api_key_name` | API key name from config |
| `http_status` | response status |
| `count` | SELECT row count or mutation affected count on success; null on failure |
| `error_code` | Public application code returned to the caller, or null |
| `error_message` | Matching public response message, or null on success |
| `duration_ms` | Non-negative request duration in milliseconds |

For REST and HTTP-level MCP errors, `error_code` and `error_message` match the HTTP `error.code` and `error.message`. For MCP JSON-RPC errors they match `error.data.code` and `error.message`; for MCP tool execution errors they match the public agent code/message, whether carried in the text result on `2025-03-26` or in `result.structuredContent.error` on the two newer versions.

Gateway stdout excludes submitted param values, URL paths, SQL, DB credentials, agent raw detail, plaintext API keys, and agent private keys. See [Gateway Logs](/gateway/logs) for the rules that determine when REST, MCP, and control events are emitted.

Control events:

| Event | Fields | Description |
|---|---|---|
| `openapi_cached` | `paths` | Emitted after Gateway caches the completed public OpenAPI document. This is always summary-only. |
| `openapi_snapshot` | `paths`, `openapi` | Emitted only when `GATEWAY_EMIT_OPENAPI_SNAPSHOT=true`. `openapi` contains the public document for all exposed capabilities, including Gateway-added `servers`, `securitySchemes`, and `security`. |
| `mcp_http_rejected` | `http_status`, `error_code`, `error_message` | Safe MCP HTTP-boundary diagnostic. It is a control event, not a request event. |

`openapi_snapshot` is not filtered per API key. The Agent excludes capabilities hidden by `expose_in_openapi: false`, but the event may contain public descriptions, parameter/result schemas, annotations, and examples for every exposed capability. It must not contain SQL, secrets, or DB connection information.

## Agent

Agent local detail log:

```text
onprest-agent.log
```

Rotation is controlled by:

```yaml
logging:
  max_size: 10MB
  max_files: 3
```

`max_size` defaults to `10MB`; `max_files` defaults to `3`. Agent stdout is for process-level events. DB-specific runtime detail belongs in the rotating local detail log. OS service managers may redirect agent stdout/stderr to separate process log files; those files do not replace `onprest-agent.log`.

The standalone `validate` and `doctor` commands use separate, non-rotating diagnostic files. See [Agent Local Logs](/agent/local-logs) for their lifecycle and access controls.
