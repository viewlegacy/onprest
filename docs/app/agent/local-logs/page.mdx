# Agent Local Logs

Agent detail logs live next to the `onprest-agent` binary.

```text
onprest-agent.log
onprest-agent.log.1
onprest-agent.log.2
onprest-agent.log.3
```

The local log is the place for DB-specific and SQL execution detail. Gateway stdout and HTTP responses intentionally omit those details.

Standalone diagnostics use separate files in the same directory:

| Command | Latest failure | Managed temporary and lock files |
|---|---|---|
| `validate` | `onprest-agent.validate.log` | `.onprest-agent.validate.<run-id>.tmp`, `.onprest-agent.validate.lock` |
| `doctor` | `onprest-agent.doctor.log` | `.onprest-agent.doctor.<run-id>.tmp`, `.onprest-agent.doctor.lock` |

Each command keeps only its latest completed, recordable failure. A later recordable failure replaces it atomically, and a fully completed success deletes it. Configuration and busy failures do not replace an older fixed log. Temporary and lock files are managed by the command and must not be edited, renamed, or removed.

When the agent runs in a terminal, process-level events such as `agent_ready` are written to stdout and fatal startup messages are written to stderr. When installed as an OS service, the service manager may redirect those streams to separate stdout/stderr files. These service stdout/stderr files are process logs, not replacements for `onprest-agent.log`.

## When Detail Is Logged

The runtime Agent writes `onprest-agent.log` detail when:

- DB ping fails at startup.
- SQL EXPLAIN fails at startup.
- Runtime capability execution fails.
- DB permissions, syntax, timeout, or connectivity errors occur.

`validate` records local preparation failures after configuration load. It returns a log path only after the current failure record has been committed. `doctor` records the same preparation failures plus Gateway diagnostic failures in its own fixed log and never changes the runtime or validation logs.

Read a diagnostic log only when the same invocation reports a recordable local failure. An older fixed log can remain after a configuration, busy, or log-finalization failure and must not be treated as the current result.

## Rotation

`capability.yaml` controls log rotation.

```yaml
logging:
  max_size: 10MB
  max_files: 3
```

When `onprest-agent.log` exceeds `logging.max_size`, agent rotates the file by size. `logging.max_files` controls how many rotated files are retained; the default is `3`.

## Operational Guidance

Treat agent local logs as sensitive operational artifacts. They may contain DB-specific detail required for debugging. Keep them on the on-prem side and do not forward them to the gateway or remote aggregation pipelines.

Runtime rotation settings do not apply to validation or doctor files. Each completed diagnostic is limited to 1 MiB. Unix creates these files with mode `0600`; Windows restricts them to the invoking user, SYSTEM, and Administrators. See [Troubleshooting](/operations/troubleshooting) for failure-specific actions.
