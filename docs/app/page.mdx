# Onprest

> Expose capabilities, not your on-prem.

Onprest lets external applications and AI agents call selected operations inside an on-premises or private network through REST and MCP, without opening an inbound port.

Each operation is a **capability** that you define in `capability.yaml` on the on-prem side: a SQL statement, a CSV filter, a folder read or save, a call to an internal HTTP API, or a WebAssembly module you wrote. Callers see its name and schema, never the SQL, paths, or credentials behind it.

The OSS core is two binaries:

| Binary | Runs | Decides |
|---|---|---|
| `onprest-gateway` | Where callers can reach it. Serves REST, MCP, and OpenAPI | Who may call which capability |
| `onprest-agent` | Next to your systems. Connects out to the gateway and holds the SQL, paths, credentials, and code | What each call may do and return |
