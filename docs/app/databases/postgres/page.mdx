# PostgreSQL

Use `sources.databases.<name>.driver: postgres`.

INSERT/UPDATE/DELETE startup validation uses `EXPLAIN` and does not execute or commit the mutation. PostgreSQL `ON CONFLICT` is supported when it does not use `RETURNING`; returned count is the PostgreSQL driver's native `RowsAffected()` value.

```yaml
sources:
  databases:
    primary:
      driver: postgres
      host: localhost
      port: 5432
      name: legacy
      user: readonly_user
      password: change-me
      tls:
        mode: verify-full
        ca_file: /etc/onprest/db-ca.pem
        cert_file: /etc/onprest/db-client.pem
        key_file: /etc/onprest/db-client-key.pem
        server_name: postgres.internal.example.com
```

## SQL Parameters

Capabilities use named params like `:customer_id`. The agent converts them to PostgreSQL placeholders such as `$1`.

```yaml
executor:
  type: db
  source: primary
  sql: select id, name from customers where id = :customer_id
```

## Startup EXPLAIN

PostgreSQL capabilities are checked with `EXPLAIN` during agent startup.

If EXPLAIN fails, the agent does not connect to gateway. Detail stays in `onprest-agent.log`.

## Timestamp Results

When a PostgreSQL `timestamp without time zone` column is declared as `type: string` in `output.items.properties.<column>`, the agent preserves the timezone-free compatibility representation, for example `2026-03-15 17:45:47.123456 +0000 +0000`. A `timestamp with time zone` result uses the PostgreSQL session timezone, for example `2026-03-15 08:45:47.123456 +0000 UTC` in a UTC session. These values do not depend on the agent process timezone. SQL `NULL` remains JSON `null` for either type.

## TLS

The source's `tls.mode` accepts `disable` (default), `require`, `verify-ca`, and `verify-full`. Use `verify-full` for CA and hostname verification. The verified name is the source's `host` unless `server_name` is set. Set `ca_file` for a private CA; omitting it uses the OS trust store. `verify-ca` verifies the chain without the hostname. `cert_file` and `key_file` enable client-certificate authentication and must be supplied together. Certificate files are captured during preparation and reconnects use those captured bytes. Restrict their filesystem permissions to the Agent service account.

`require` encrypts the connection but does not provide the same server-identity guarantee as `verify-full`; it does not accept `ca_file` or `server_name`. Existing files with no `tls` section retain `sslmode=disable`. Reconnects keep the configured TLS mode and never retry in plaintext. To replace a CA or client certificate, follow the [database TLS rotation procedure](/operations/deployment#database-tls-certificate-rotation).

## Connection Environment

Configure connections in `sources.databases`. The Agent overrides `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`, `PGSSLMODE`, `PGSSLROOTCERT`, `PGSSLCERT`, and `PGSSLKEY` with captured source values. It ignores `PGPASSFILE` and the default PostgreSQL password file. An omitted or empty source password stays empty.

Remove these environment variables from the Agent service when set to nonempty values: `PGSERVICE`, `PGSERVICEFILE`, `PGAPPNAME`, `PGCONNECT_TIMEOUT`, `PGSSLSNI`, `PGSSLPASSWORD`, `PGSSLNEGOTIATION`, `PGTARGETSESSIONATTRS`, `PGTZ`, `PGOPTIONS`, `PGMINPROTOCOLVERSION`, `PGMAXPROTOCOLVERSION`, `PGCHANNELBINDING`, and `PGREQUIREAUTH`. Startup, `validate`, and `doctor` reject them before parsing connection settings or reading service files. This keeps the definition hash and actual connection settings consistent; diagnostics identify the variable without exposing its value.

```bash
go test -tags=integration ./it/... -args -onprest-it-db=postgres
```
