# REST API

Execute a prepared capability with `POST /api/v1/capabilities/{name}`, `Authorization: Bearer {api_key}` (or `X-API-Key`), and `Content-Type: application/json`. The body is the input object directly:

```json
{
  "id": 1
}
```

Input follows the capability schema. Duplicate keys, invalid UTF-8, signed-int64 overflow, extra top-level values and non-object bodies are rejected. The Gateway body limit defaults to 1 MiB and uses `GATEWAY_MAX_REQUEST_BODY_BYTES`; wire-body overflow returns HTTP 413 `LIMIT_EXCEEDED`, and an unsupported REST content type returns HTTP 415 `INVALID_REQUEST`. Capability input limits are also enforced by the Agent.

## Success response

```json
{
  "request_id": "01J5ABCDEF1234567890ABCDEF01",
  "result": {
    "data": {
      "rows": [
        {
          "id": 1,
          "name": "Ada Lovelace"
        }
      ],
      "count": 1
    },
    "files": []
  }
}
```

The Gateway assigns one request ID for the public response, Agent request and request log. SELECT data is a rows/count object; DML data is `{"count": n}` using native RowsAffected, including zero. Output selection and constraints come from `output`. Omitted output returns `data: null` and an empty files array while still executing. The current DB runtime publishes JSON only. See [Database JSON values](/databases#json-values) for the representation of database types.

## Failure response

```json
{
  "request_id": "01J5ABCDEF1234567890ABCDEF01",
  "error": {
    "code": "LIMIT_EXCEEDED",
    "message": "output exceeds configured limit",
    "outcome": "rolled_back"
  }
}
```

Success and error are mutually exclusive. Errors contain safe code/message/outcome and optionally a fixed safe reason. See [Errors](/api/errors) for status mappings and outcomes. Driver errors, SQL, source details, credentials and input values remain in local diagnostics.

The deadline uses the prepared capability's timeout and caller cancellation. SELECT max_rows truncates results. DML validates count, common output and limits before commit; a confirmed rollback is reported explicitly. After an unknown outcome, verify state through an independent read before retrying a mutation.
