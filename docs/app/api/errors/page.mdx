# Errors

REST and HTTP-level failures return a shared error envelope with a Gateway-assigned `request_id` and `error.code`, `message`, `outcome`, and optional fixed safe `reason`. Success has `result` instead of `error`.

```json
{
  "request_id": "01J5ABCDEF1234567890ABCDEF01",
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "input validation failed",
    "outcome": "not_started"
  }
}
```

| HTTP | Code | Meaning |
|---:|---|---|
| 400 | `INVALID_REQUEST`, `VALIDATION_FAILED` | Invalid request or capability input |
| 401 | `AUTH_FAILED` | Missing or invalid authentication |
| 403 | `CAPABILITY_DENIED`, `PERMISSION_DENIED` | Capability, origin or IP permission denied |
| 404 | `NOT_FOUND` | Capability is not defined |
| 409 | `SOURCE_CHANGED`, `CONFLICT` | Definition/source mismatch or typed DB integrity constraint |
| 422 | `LIMIT_EXCEEDED`, `APP_*` | Capability limit or valid application failure |
| 429 | `RATE_LIMITED` | Gateway or capability rate admission rejected |
| 503 | `BUSY`, `AGENT_OFFLINE`, `DEPENDENCY_UNAVAILABLE` | Capacity, Agent or database unavailable |
| 504 | `EXECUTION_TIMEOUT` | Execution deadline exceeded |
| 502 | `EXECUTION_FAILED`, `OUTPUT_INVALID`, `OUTCOME_UNKNOWN` | Execution/output failure or uncertain transaction |
| 500 | `INTERNAL_ERROR` | Unexpected internal failure |

REST wire-body overflow uses HTTP 413 `LIMIT_EXCEEDED`; unsupported content type uses HTTP 415 `INVALID_REQUEST`; disallowed methods use HTTP 405. MCP HTTP negotiation can use 400/403/405/406. A duplicate Agent connection uses 409.

## Observed outcome

| Outcome | Meaning |
|---|---|
| `not_started` | Business execution did not begin |
| `no_change` | No business change was observed |
| `rolled_back` | All business effects were confirmed rolled back |
| `committed` | All business effects were confirmed complete |
| `unknown` | Completion or rollback could not be confirmed |

Do not infer outcome from the error code or a readonly/idempotent annotation. DML output and capacity errors occur before commit and report confirmed rollback when available. Commit/rollback uncertainty takes priority over timeout and returns `OUTCOME_UNKNOWN`. Gateway timeout or an in-flight disconnect may be `unknown`. Verify database state independently before retrying an uncertain mutation. A completed commit is not automatically re-executed.

The public message and reason do not contain driver text, SQL, constraint names, source paths, secrets or submitted values. Branch on code and observed outcome; use [Agent local logs](/agent/local-logs) for private diagnosis. Malformed Agent error/result frames are rejected rather than forwarded.

## MCP

A tools/call business failure, including an undefined tool name, is a result with `isError: true`, and one text item containing the same JSON error envelope. Versions `2025-06-18` and `2025-11-25` also put that envelope in `structuredContent`; `2025-03-26` omits structured content. HTTP status is normally 200 for these tool results.

JSON-RPC parse/shape/method-parameter failures keep their own layer: -32700 PARSE_ERROR, -32600 INVALID_REQUEST, -32601 METHOD_NOT_FOUND, and -32602 INVALID_PARAMS. JSON-RPC ID is independent of the Gateway request ID. Valid recognized notifications return HTTP 202; invalid recognized idless notification parameters return HTTP 400 with -32602 and id null. See [MCP](/api/mcp).
