# OpenAPI

The gateway exposes an API-key-filtered OpenAPI document.

## Endpoint

```http
GET /openapi.json
Authorization: Bearer {api_key}
```

## Source

The Agent generates OpenAPI from `capability.yaml`, excluding capabilities with `policy.expose_in_openapi: false`. When the Agent connects, the Gateway retrieves and caches the generated document in memory.

The Gateway validates the document and its capability metadata before caching them. Until valid metadata and definition hashes are available, business calls return `AGENT_OFFLINE` without execution. If metadata requires file references but `ONPREST_PUBLIC_BASE_URL` is missing, the Gateway rejects the whole metadata set: capabilities remain unavailable and are not advertised, and calls return `DEPENDENCY_UNAVAILABLE` without execution. See [File Output](/api/files) and [File Reference Origin](/gateway/configuration#file-reference-origin). A service whose capabilities are all hidden can have an empty OpenAPI `paths` map while retaining its internal capability metadata.

For JSON and reference delivery, the HTTP 200 `application/json` schema describes the common envelope: `request_id` and `result`, with `result.data` and `result.files` always present. Configured `output` determines the schema of published data. A SELECT with data output returns `result.data.rows` and a non-negative `int64` `result.data.count`; INSERT/UPDATE/DELETE data output returns the native affected-row count in `result.data.count`. Omitting output returns `result.data: null` and `result.files: []` while still executing the operation.

REST direct delivery instead advertises the configured binary media type and binary response schema for HTTP 200, and returns the file bytes without a JSON envelope. See [File Output](/api/files).

Optional `x-onprest-annotations` contains explicitly configured operation hints, and optional `x-onprest-examples` contains validated `{params: object}` examples.

## Filtering

`/openapi.json` is filtered by API key authorization.

If an API key can call only `get_customer`, paths for other capabilities are removed from the returned spec. If a capability has `policy.expose_in_openapi: false`, it is not exposed through OpenAPI or MCP `tools/list`.

## Gateway Metadata

Gateway adds:

- `servers` using `GATEWAY_PUBLIC_URL`, or a fallback derived from `GATEWAY_ADDR`
- `components.securitySchemes.bearerAuth` for `Authorization: Bearer {api_key}`
- `components.securitySchemes.apiKeyAuth` for `X-API-Key: {api_key}`
- top-level `security` requiring either auth scheme

The cached document also feeds the optional `openapi_snapshot` stdout event. See [Logging Reference](/reference/logging) for its exposure boundary.

## Sensitive Data

OpenAPI metadata must not include:

- SQL text
- DB host, user, password, or DSN
- agent private key
- runtime params
- agent error detail

Annotations and examples are public metadata and must not contain secrets.

The spec is a public contract for allowed capability calls, not a mirror of `capability.yaml`.
