# Capability Changes

The agent reads `capability.yaml` only at startup. To change a capability, edit the file, validate it, and restart the agent. The command below stops the running agent only if validation succeeds, so a broken file never takes a working agent offline.

## Apply a change

Edit the file registered with the service, then run as an administrator:

```bash
CAPABILITY_FILE=/absolute/path/capability.yaml

onprest-agent validate --config "$CAPABILITY_FILE" &&
  onprest-agent service stop &&
  onprest-agent service start &&
  onprest-agent service status
```

Validation runs while the current agent stays online. If it fails, nothing else runs; fix the file using the message it printed, and the log file it names, if any. See [Troubleshooting](/operations/troubleshooting#agent-fails-at-startup-or-validate).

- If you added a capability, also add it to the callers' API keys and restart the gateway; see [API Keys](/gateway/api-keys).
- Download links issued before the restart stop working.

If the agent is not installed as a service yet, see [Run the agent as a service](/operations/deployment#run-the-agent-as-a-service).

## Check the result

After the restart, check that the gateway sees the new definition:

```bash
GATEWAY_URL=https://gateway.example.com
ONPREST_API_KEY=replace-with-plaintext-api-key
CAPABILITY_NAME=get_customer
CAPABILITY_ARGS='{"customer_id":1}'

curl --fail-with-body -sS "$GATEWAY_URL/healthz"
curl --fail-with-body -sS \
  -H "Authorization: Bearer $ONPREST_API_KEY" \
  "$GATEWAY_URL/openapi.json"
curl --fail-with-body -sS \
  -X POST "$GATEWAY_URL/api/v1/capabilities/$CAPABILITY_NAME" \
  -H "Authorization: Bearer $ONPREST_API_KEY" \
  -H "Content-Type: application/json" \
  -d "$CAPABILITY_ARGS"
curl --fail-with-body -sS \
  -X POST "$GATEWAY_URL/mcp" \
  -H "Authorization: Bearer $ONPREST_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "MCP-Protocol-Version: 2025-11-25" \
  -d "{\"jsonrpc\":\"2.0\",\"id\":1,\"method\":\"tools/call\",\"params\":{\"name\":\"$CAPABILITY_NAME\",\"arguments\":$CAPABILITY_ARGS}}"
```

`/healthz` should report `agent_connected: true`, and OpenAPI should show the new contract. An MCP tool error still returns HTTP 200 with `isError: true`, so read the body, not just curl's exit code.

An agent restarted without validation that fails at startup stays offline, and `/healthz` reports `agent_connected: false` until a valid file is in place.
