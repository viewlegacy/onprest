# Release Gate

Contributors run tests affected by their changes locally. The complete gate runs in GitHub Actions; a full local release gate is not required before opening or updating a PR. Users install the two published binaries without Go or a source checkout; see [Install from a release](/operations/deployment#install-from-a-release).

## GitHub Actions

Pull requests to `main` run one gate per update. Feature-branch pushes do not start a second copy. A new PR commit cancels its previous gate. Pushes to `main`, manual runs and weekly runs validate the complete commit, independent of changed paths.

| Check | Scope |
|---|---|
| `ci / unit` and `ci / agent` | Common tests with pinned public OpenAPI/MCP schema validation enabled once, plus vet; Agent tests use two partitions |
| `ci / author-cli` | Independent real author workflows for build, execution and file handling |
| `ci / wasm` | Six disjoint partitions of the Wasm suite |
| `ci / repository` | Repository contracts, archive verification and rejection of unsafe/corrupt archives |
| `ci / sdk` | Independent SDK race tests, vet, module verification and WASI build |
| `package-candidate` | Five OS/CPU binary archives, Quick Start archive, source and ten-binary vulnerability scans and checksums |
| `integration-linux` | Four PostgreSQL E2E partitions, four database-specific conformance/TLS jobs, Docker/Compose, extracted Quick Start, and DB interruption stability |
| `native-tests` | Filesystem, spool, OS permissions, recovery, author CLI, real WASI and process/resource boundaries on Linux arm64, macOS and Windows |
| `service-lifecycle` | Actual systemd, launchd and Windows Service lifecycle using archived binaries, a real gateway and PostgreSQL |
| `docs` | Documentation site build when applicable |
| `checks` | Requires every selected job to succeed; rejects failures and cancellations |
| `release-ready` | Publication evidence from a complete non-PR run of the exact commit |

Docs-only PRs run the documentation build. Gateway-only changes can omit unrelated native Agent tests. Unknown paths and shared dependencies conservatively select native tests. PRs validate the merge result. They do not produce tag-commit `release-ready` evidence; the full `main` or manual run supplies it. Configure the required PR status check as `checks`.

Regular suites run once. Only the DB interruption stability case repeats five times. The four-database TLS contract covers PostgreSQL, MySQL, SQL Server and Oracle, including trust/hostname errors, supported client certificates, rotation and reconnect without plaintext downgrade. Container-backed partitions require Docker, reject skipped tests and check for leftover Testcontainers resources.

Go test jobs retain JSONL logs and elapsed-time summaries even when successful. Their timeout budget is ten minutes, with an eight-minute test timeout; these budgets do not guarantee wall time including runner queues and downloads. The PR target is five minutes, with ten minutes as the upper target. Cross-builds do not prove native runtime compatibility or minimum-version OS support; see [supported platforms](/operations/deployment#supported-platforms).

## Targeted Local Checks

Use the relevant commands in [Test Commands](/reference/test-commands). For example:

```bash
go test ./internal/contract -run '^TestPublic' -count=1
go test ./internal/agent -run '^TestCodeCLIRealAuthorWorkflowBuild$' -count=1
```

Maintainers can run integration partitions explicitly:

```bash
bash scripts/it_release_gate.sh postgres-1
bash scripts/it_release_gate.sh db-mysql
```

Partitions need Go, Docker, and, for schema validation, Node.js with the pinned Ajv dependencies installed:

```bash
npm ci --ignore-scripts --no-audit --no-fund --prefix internal/contract/testdata/schema-validator
```

`make test-it-release-gate` runs all integration partitions sequentially as a maintainer convenience. It does not rerun unit tests or vulnerability scans and does not establish full release readiness. `quickstart` additionally requires extracted distribution binaries and the Quick Start archive, which CI supplies.

## Release Publication

A semantic version tag (`vX.Y.Z`) starts publication. It requires a successful `release-ready` for the exact tagged commit SHA. A missing, failed, canceled, partial or different-SHA gate cannot authorize publication. The workflow checks the final tagged archive bytes with Linux distribution integration and all three service managers, attests that byte set, publishes `SHA256SUMS`, and refuses to overwrite an existing Release.

Release packaging requires Go 1.26.10 or later as declared in `go.mod`. CI uses that file for the Go toolchain. The vulnerability scanner is pinned as a Go tool dependency, and packaging rejects reachable known source or distributed-binary vulnerabilities.
