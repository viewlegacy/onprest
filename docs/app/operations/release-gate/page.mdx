# How Releases Are Checked

Published Onprest releases contain prebuilt Gateway and Agent binaries for
Linux, macOS, and Windows, plus a separate Quick Start asset. Users do not
need Go or the source repository to install them.

Before publication, GitHub Actions builds the five OS/CPU archives, checks
their contents and versions, scans the distributed binaries for known
vulnerabilities, and runs database-backed integration and native service
checks. The Quick Start asset is exercised with a released binary archive
against a disposable PostgreSQL database.

A version tag starts the release workflow only after the `release-ready` gate
has succeeded for that exact commit. The workflow then tests the tagged
artifacts and publishes the GitHub Release. `SHA256SUMS` and GitHub artifact
attestations are provided for operators who choose to verify their downloads;
verification is not required to install Onprest.

For installation, use [Deployment](/operations/deployment). Contributors and
maintainers can find runnable commands in [Test Commands](/reference/test-commands).
