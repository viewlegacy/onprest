# Release Gate

Maintainers use the release gate before treating an OSS core change as operationally ready. Users install published releases without Go or the source repository; see [Install from a release](/operations/deployment#install-from-a-release).

Contributors run only the tests their change affects locally. Every pull request to `main` runs the gate in GitHub Actions, so a full local run is not required.

## Release Gate Command

```bash
make test-it-release-gate
```

This command runs the Linux integration partitions one after another and verifies:

- PostgreSQL integration tests
- public schema validation: the PostgreSQL integration tests check real values against the published OpenAPI and MCP schemas
- PostgreSQL DB interruption stability 5 consecutive times
- all-DB conformance: every `TestContainerDBDriver*` case, including Oracle immediate transaction start/cancel, PostgreSQL nullable Agent response/OpenAPI 3.1 validation, and PostgreSQL timestamp JSON/timezone compatibility
- MySQL special-character credential connection
- the four-database TLS contract against real databases: `disable`, `require`, and `verify-full` for PostgreSQL, MySQL, SQL Server, and Oracle, plus PostgreSQL `verify-ca`
- encryption observation, private/wrong CA, hostname and `server_name`, expiry, certificate replacement/pool recreation, reconnect without plaintext downgrade, and supported PostgreSQL/MySQL client-certificate authentication
- Oracle TCPS through the pure-Go driver without Oracle Instant Client
- Docker image operational tests
- Docker Compose env-file operational tests
- test/subtest skip count is zero in required mode
- testcontainers residue is zero
- when given extracted release binaries, the Quick Start runs against those binaries outside the source tree

Unit tests and vulnerability analysis run as separate checks; see [GitHub Actions](#github-actions). To run a single partition, pass its name: `postgres-1` to `postgres-4`, `db-postgres`, `db-mysql`, `db-sqlserver`, `db-oracle`, `docker`, `stability`, or `quickstart`.

```bash
bash scripts/it_release_gate.sh db-mysql
```

## GitHub Actions

Pull requests targeting `main`, pushes to `main`, manual runs, and a weekly schedule run these checks. A new commit on a pull request cancels the previous run.

| Check | Scope |
|---|---|
| `release-gate / ci / *` | Runs `go test` with public schema validation and `go vet`, split into parallel jobs, plus race tests, vet, and the WASI build for the Go SDK |
| `release-gate / package-candidate` | Builds the five OS/CPU archives and the Quick Start archive, scans the source and the ten distributed binaries for vulnerabilities, and verifies checksums |
| `release-gate / integration-linux` | Runs the `make test-it-release-gate` partitions in parallel on Linux with the binaries extracted from the Linux amd64 archive |
| `service-lifecycle / linux-systemd` | Installs, starts, inspects, stops, and removes the agent with systemd |
| `service-lifecycle / macos-launchd` | Runs the same lifecycle with launchd |
| `service-lifecycle / windows-service` | Runs the same lifecycle with Windows Service |
| `release-gate / native-tests` | Runs the agent's OS-dependent tests natively on Linux arm64, macOS, and Windows; a skipped test fails the check |
| `release-gate / docs` | Builds the documentation site |
| `release-gate / checks` | Requires every job selected for the run to succeed; use it as the required status check for pull requests |
| `release-gate / release-ready` | Runs only outside pull requests; requires `checks` to succeed with every job selected |

The three service checks run the binaries from the release archives under the native OS service manager, against a real gateway and PostgreSQL.

A pull request runs only the checks its changes can affect. A documentation-only change runs `docs`, and a change limited to the gateway, integration tests, or release tooling skips `native-tests`. Pushes to `main`, manual runs, and scheduled runs execute every check.

Cross-builds do not prove native runtime compatibility. Before release, verify the exact candidate on each [supported OS baseline](/operations/deployment#supported-platforms); results from a newer OS do not establish minimum-version support.

## Release Publication

A semantic version tag (`vX.Y.Z`) starts the release workflow. Publication
requires a successful `release-ready` result for the exact tagged commit SHA;
missing, failed, canceled, or different-SHA results block the release. The
workflow rebuilds and checks the tagged assets, attaches a GitHub artifact
attestation to each asset, publishes `SHA256SUMS`, and creates the GitHub
Release. It never overwrites an existing Release.

## Requirements

Release gate commands require Go 1.26.10 or later as declared in `go.mod`. Schema validation also needs Node.js and npm to install the pinned validator. `make test-it-release-gate` installs it; before running a single partition or `make test-it-postgres-ci`, run `npm ci --ignore-scripts --prefix internal/contract/testdata/schema-validator`. CI reads `go.mod` as the Go version source of truth, and Docker builds use the same Go 1.26.10 builder image pinned by digest. The `govulncheck` scanner version is pinned as a Go tool dependency and is executed by the `package-candidate` check.

Container-backed tests require Docker daemon access. To make container availability mandatory, use:

```bash
ONPREST_IT_REQUIRE_CONTAINERS=1
```

If Docker is unavailable and mandatory mode is not enabled, container-backed tests may skip. Required release gates should run with no skipped integration or operational cases.

## Acceptance Criteria

A release candidate should pass `integration-linux`, the native tests, all three native service checks, and the final `release-ready` aggregation for the exact candidate commit, and preserve the architecture boundaries:

- zero reachable known vulnerabilities reported by `govulncheck ./...`
- two deployable binaries: `onprest-gateway` and `onprest-agent`
- no gateway SQL construction
- no gateway DB credentials
- direct and reverse-proxy deployment both remain valid
- error detail redaction remains intact
